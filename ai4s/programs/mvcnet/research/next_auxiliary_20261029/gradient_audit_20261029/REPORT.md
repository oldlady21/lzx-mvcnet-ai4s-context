## 1. CMC梯度接收端符合设计

在两个原生实例中，四臂数值前向、CE/CVC分量及其对F/A表示的梯度、BN buffers、随机状态均与原生参考精确一致。仅CMC反向接收端不同。

| 条件 | CMC→F | CMC→encoder/projector | CMC→分类头C |
|---|---|---|---|
| S0 | 非零 | 非零/非零 | 无 |
| P0 | 无 | 非零/非零 | 无 |
| R0 | 非零 | 无/无 | 无 |
| N0 | 无 | 无/无 | 无 |

B2下，S0的CMC梯度范数F=2.299646、encoder=2.377576、projector=23.768705；P0的F为0、另外两项与S0相同；R0相反；N0三者为0。B4给出同一接收模式。分类头本就不直接参与CMC，四臂均为0，不能把它误称为P0新增的保护。

CE继续进入F，CVC继续进入F和A。例如B2的CVC对表示的梯度范数为F=0.099058、A=0.131783，B4为0.077817、0.100298；各臂相同。P0不是冻结主干，N0不是删除辅助模型。

用直接余弦相似度矩阵和logsumexp独立构造的双向anchor参考，与原NT-Xent的P0梯度在float64容差内一致。故“单向”仅指接收端，不是只保留半数anchor。故意删去另一半anchor会改变梯度，三个实例均被拒绝。

## 2. S0与原生一致；P0/N0首步主干及Adam等价

- 两个原生实例的S0与独立调用的原生参考，在全部模块的梯度、一次更新后参数、Adam step/exp_avg/exp_avg_sq上SHA256完全一致；损失、BN buffers、CPU/CUDA随机状态也一致。
- P0/N0在F和C的全部参数梯度、更新后参数以及Adam状态上精确一致。两者encoder/projector的更新后参数不同，说明不是四臂都被误接成同一个目标。
- 保存的F/C核心技术状态被第二个脚本逐tensor复查为相等，原始梯度/Adam摘要也重新读取核对。
- 对已保存摘要再做四组因子配对：S0/R0的F/C、S0/P0的encoder/projector、R0/N0的encoder/projector、P0/N0的F/C，均检查梯度、更新后参数和Adam状态；两个实例共8组完全一致，见 `FIRST_STEP_FACTORIAL_VERIFICATION.json`。该复查不增加模型运行。

这验证的是**同初始化、同输入/RNG、空Adam状态的一次技术更新**。不是对不同既有动量状态、完整训练轨迹或生产入口端到端运行的等价证明。参考与候选共享原生模块及损失实现；独立余弦/logsumexp参考补查了表示层损失，但不把它称为独立复现了整个模型。

## 3. CVC间接路径存在，并通过断路负对照

在P0/N0分别完成一次技术更新后，用相同新合成输入和相同随机状态取得两个辅助表示。再固定同一个已更新的F/C与F前向随机状态，只交换辅助表示，重算CVC对主干参数的梯度：

| 原生实例 | 交换A引起的F梯度差范数 | 相对N0梯度范数 | 将A固定回同一值 | 断开跨分支耦合后交换A |
|---|---:|---:|---:|---:|
| B2 | 0.83611075 | 0.64733202 | 0 | 0 |
| B4 | 0.42808849 | 0.43947710 | 0 | 0 |

第二个脚本直接读取保存的技术张量，独立构造F前向与CVC，精确重现以上两项差值。断路对照把CVC替换为两条互不耦合的分支内CVC，仅用于审计反例：A仍可出现在自己的损失中，但无法改变F梯度；两实例差值确为0。该反例不会进入训练矩阵，也不用于改写旧损失实验。

表示层另用混合导数与中心有限差分交叉核验CVC的F–A依赖，三个实例误差约7.61e-11、8.92e-12、1.00e-10，均通过事先脚本中的1e-7+1e-5相对容差。

因此，“P0/N0首步主干相同，所以之后必然相同”的退化解释在这些实例中不成立。**这些范数不是准确率改善，也不表明变化方向有益**；对齐辅助表示也可能改变原CVC碰撞几何并损害分类。第二次F优化器更新未执行，不把梯度重放写成二步训练结果。

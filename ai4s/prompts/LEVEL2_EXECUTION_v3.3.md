# AI4S 执行与续接规范 v3.3

仅在唯一 Prompt Index 为对应 Program 选定兼容的 L1/L2/L3 后生效。沿用 Transaction v2、`evidence_to_design_v1` 和现有接口；以下研究步骤不是新增状态枚举或自动执行能力。冻结工作始终用其原链与合同。

## 1. 绑定对象，读取当前需要的证据

从 `ai4s/PROMPT_INDEX.yaml` 进入，对照 Program、State 的 active_run／active_operation／campaign／冻结续接选链，再按 Evidence Index 的精确引用定位材料。运行状态看 State，证据看 Evidence Index，正式 Claim 看 Claim Ledger；简报、PAPER 和目录日期不替代这些来源。

观察用 `scripts/ai4s/program_controller.py --program <program> next-action`；旧 `resume-plan` 可能写状态，不能用于只读查询。同一工作增量读取变化，旧路径按 `ai4s/archive/PATH_MAP.json` 解析。身份冲突先限定受影响范围，不扫描全部历史寻找一个看似最新的对象。

选型前先核对材料的数据角色、用途和 exposure，再读取正文及摘要；无法判定角色先核对来源。最终评价结果不进入选型上下文。已获准的结果分析与写作使用各自允许材料，不把其派生摘要自动交回选型。

## 2. 用现有 brief 完成一页决策

在单份 `research_brief` 中维护以下内容，已有字段直接复用，复杂设计按需展开，不以一页字数上限省略关键科学内容：

| 内容 | 要回答的问题 |
|---|---|
| 当前问题与论文价值 | 对应哪句拟议 Primary Claim 或哪项成文关键缺口？本次在建立主方法、补关键证据还是解决具体局限，为什么优先？ |
| 当前认识 | 引用稳定研究总览中的相关认识及直接 evidence ID／来源版本；这些认识具体改变了什么设计、对照或投入？解释与未知分开。 |
| 关键未知与行动 | 哪些解释尚未区分；为什么选择本次实验、重分析、控制、停止或写作？只比较实际相关的选项。 |
| 方法与实施 | 宿主、作用路径、必要配套、近邻方法及主比较；增量归因如何恢复声明对照？ |
| 最小充分设计 | 必要控制、延后证据及理由、固定配置集合、合法数据范围、配对与选模、指标单位、阶段成本。 |
| 结果与处置 | 不同可能结果对应什么判断和行动；继续／停止条件、预算、范围与授权是什么？ |

先用已有证据形成判断，再决定是否需要新增实验。不为停止、写作或只读重分析虚构候选和训练合同。尚未决定实验时保留设计记录即可。

用户要求生成新方向、主问题尚无可比较方案，或连续近邻改动未产生新的机制解释时，默认经项目 router 限定调用 idea-creator 的视角构思、候选生成与合并。已有明确高价值下一步时直接推进；用户给定具体 idea 时先具体化，只有关键替代解释尚未覆盖才补构思。以上不按固定失败次数触发。Foundry 仍由用户独立调用并选择交接；Program 不自动启动 Foundry。同一问题、来源和范围的有效构思复用，不串成每轮必经技能链。输入、适配阶段和返回位置统一见 [项目技能路由](MIEEG_AI4S_SKILL_ROUTER.md#新方向构思的限定调用)。

拟议主张在 brief／研究总览用自然语言表达即可，不为探索新建正式 Claim Ledger、评分表或审批门。有候选但主贡献依据不足时，比较补关键证据与辅助创新的价值；提出辅助模块须说明它解决主线什么局限，不能只说“增加创新点”。相似路线引用精确历史边界并说明实质差异；无关历史不强行纳入。

筛查、复核、归因和正式评价按当前问题选择，不新增 D0–D4 状态或逐级审批。关键控制不能延后到使初筛无法解释；seed、对象及训练长度按作用阶段和主要波动来源选择。描述成本时区分完整训练、冻结特征／轻量拟合、技术节点和分析，不直接用任务数比较算力。

每个实际阻断门只说明其阶段、对照／单位、阈值依据、触发动作和范围；重复门合并，解释性指标保留为诊断。完整性、无泄漏、公平比较及冻结不可接受风险仍须满足。与实际判定分支有改动时，验证相关正常边界及错误反例；不因改文字重复执行无关测试。

新合同冻结前，在原 brief／准备记录中把“拟议主张 → 指标与统计单位 → 阻断条件及观测项 → 实际分析／分类函数与合同识别分支”对应起来，引用所用实现版本；复用已有字段与覆盖，不新增合同字段或台账。沿 `scripts/ai4s/program_controller.py` 的 `command_apply_decision` 核对该合同进入的真实分支；通用 `classify_round` 有正均值及双 seed 同向等预设，不适用于所有机制、条件性或简化主张，正式评估有其独立入口。不得仅改文案就沿不适用的默认分类器执行。

需要专用判定时，先确认已有显式接线是否覆盖；缺少则标明工程缺口，在原授权内补齐最小接线并按第4节验证，涉及范围变更按原规则处理。新建／改变判定路径只检查受影响分支，至少覆盖一项合法达标情形和一项应被拒绝的情形，证明实际消费者按预定规则区分；合成样例只证明工程语义。尚未接通时只阻断依赖该判定的派发，不登记科学 NO_SIGNAL、不增加无关对照来迎合旧解析器，也不通过事后换门补救。旧冻结 Run 的判定器与规则保持原样。

简报保存理由，唯一冻结科学配置保存执行数值。现有 v3 `SCREEN_NEW` 绑定 brief 路径与 SHA-256；旧链保留三卡规则。准备器从完整合同生成 Bundle，不自动从自由文本生成科学合同。

## 3. 在已授权范围内固定实验

优先使用现有合同能表达的一个或有限多个完整配置，不预建动态搜索引擎。查看效果前明确配置闭集、选择方式、对照、预算和停止条件。假设、具体干预、配置及 seed 在原记录中分清即可，不新增三套台账；全部尝试和选择机会保留，拆名字不增加名额。

必要适配可共同变化，按完整适配包解释；只在相应控制支持时归因于单一组件。张量形状能运行不代表信息轴、融合位置、初始化、参数共享或训练配套合理。官方权重及专属配方按 L1 记录真实来源、载入与数据接触。

结果后新增配置或新假设属于后续计划，不能补进原冻结矩阵。值得继续但缺预算／范围的对象记明缺口，不记科学失败或当前可运行 pending。最终评价不选择最佳配置、seed 或对象。

新执行授权的 `research_scope` 沿现有接口明确 question、data、stage、module 与 allow_new_module；新合同 `governance_binding` 绑定 chain、policy、campaign、question、data。字段和校验以 [TRANSACTION_RUNTIME.md](TRANSACTION_RUNTIME.md)“授权与自动推进”为准，不创造替代授权。

## 4. 执行与验收：复用真实通路

执行顺序保持：**必要检查 → 冻结合同与不可变 Bundle → upload／launch／probe → fetch／manifest verify → verified intake → 身份与任务闭集核验 → 分析与决策**。

各 Program 的新合同须在冻结前运行 `python scripts/ai4s/transaction.py validate-new --contract <合同路径>`，显式填写共享模板的 `execution.result_transfer.mode=analysis_v1`、实际分析依赖 `include`、包上限和核验超时。漏填、空清单、占位符或非法上限会阻断冻结续接、打包及新 Run 登记；沿用旧合同起草新身份时同样检查。规则与验收入口统一见 runtime“精简回传”。新合同使用该策略：按分析实际依赖填写回传清单，服务器核验完整产物，本地核验所选证据；完整本地归档不再是分析前提。实施与保留边界见 `TRANSACTION_RUNTIME.md`“精简回传”；缺少该字段的旧冻结合同仍全量验收。模型推理复核和恢复训练按需取得对应资产，精简验收不自动授权远端分析、额外诊断或清理历史文件。

每个 Transaction 只容纳一个科学决策阶段，冻结技术依赖、科学停止点、`intermediate_effect_reading=false` 和 `post_intake` 三门。下一阶段在 intake、分析与决策后另建冻结 Transaction；内部技术依赖不增加逐节点人工确认。

按本次变化选择检查，已有覆盖在源码、接口、环境与任务家族仍适用时复用。新增或变更执行路径用最终 Bundle 的实际 argv、合同、真实写入者／消费者及节点汇总器验证最小合法闭环，覆盖受影响 arm、阶段和复用分支，不遍历全部科学任务。记录输入身份、命令、覆盖终点及缺口；相关字节变更只重验受影响部分。

涉及字段新增、类型、层级、单位或函数返回值变化时，在现有准备记录中列受影响字段的写入者、封装／调度补写者、读取者和实际样例；沿真实写入函数走到补写、汇总、回传选择及分析／复用读取终点。用历史脱敏小工件或从实际生产函数生成的 CPU 小样本；手工拼出消费者期待的 JSON、只验 argv/parser 或只到 task 成功，不算覆盖该接口。只测本次受影响分支，保留一个合法样例和一个本次真实故障反例，不增加一套审批或大规模仿真。字段原则与轻量回归入口统一见 runtime“字段接口与产物闭环”。

共享接口存在不等于 Program 已接线。新 Bundle 的准备记录须指向实际调用及消费覆盖；尚未经过该路径的分支注明 NOT_COVERED，补最小闭环后才宣称该接口验收，不以共享单测替代 Program 专属 writer／复用／分析器检查。

检查器须接受合法边界，也须拒绝真实故障。整数语义、行序、身份和字段兼容按原合同解释；同步配对的合法未排序输入不能被误拒绝，规范化也不能悄悄改变科学训练顺序。缺字段、错配、重复成员或篡改不能靠默认值／PASS 补齐。原始产物和哈希保留。

合成 CPU 闭环只证明工程覆盖。目标设备、生产形状及完整作用路径验证按原授权的技术节点完成；缺资格时只阻断受影响派发，不声称离线覆盖了 GPU。具体执行复用 runtime 的“合同与任务产物”“执行可靠性与设置校准”“新启动接口的离线验收”和“包内资源策略摘要”；其中 v3.1 的历史引用不使本链重新加载整份旧 L2，本节规定本版检查范围。

准备、派发与恢复按 runtime“新工作的部署、预算与恢复”一次汇总真正缺项。容量、共卡、余量和重试由适用执行器与冻结合同决定；本版不附加统一预留或共卡禁令。分别记录完整进程实测、估计、竞争性 OOM 和容量限制；OOM 不自动成为永久需求下界，也不允许违背原策略调低承诺。

准备、实际执行、收尾、资源等待与人工交接分开说明，预算严格按冻结计时扣算。派发前刷新余额，不把追加总上限当作新增量、不追溯抹掉成本。资源等待及监控断线不自动登记训练失败或重发任务。

## 5. 工程恢复：先保留成果，再关闭实际缺口

“技术门未通过”只是摘要。定位精确 Run／node／task、失败阶段、首个有证据的异常或字段、预期与实际及日志；分别报告训练完成、产物写出、验收和被阻断任务。根因未知就说明未知，不把检查器报错当作模型失败。

字段冲突修写入／补写方，保留严格冲突检查；函数返回的 raw 产物与验证上下文分清，调度器不同输出形状使用显式来源适配，不猜别名。缺失字段只有在原规则允许且能从已封存来源唯一重建时，才在独立派生层重建并逐项核验；旧文件与失败回执保留，不能补默认 PASS。恢复旧 Run 仍按其冻结合同和权限，新共享函数或新模板不自动改写旧包。

恢复前在现有记录中列清已完成合格、完成待验收、运行中、未启动、失败和未知任务，核对复用资格、剩余工作与预算。已有工具可生成则复用，否则直接列明；不以先开发恢复平台为前提。观察未知先核对同一 Run，存在 checkpoint 不等于允许复用。

| 实际影响 | 处理 |
|---|---|
| 观察／同身份运输 | 在已有权限内查询或续传，冲突不混并，不重复派发。 |
| 解析／路径／分析工具错误 | 保留原件，以冻结定义重放到真实消费者和汇总器；记录修复代码与派生结果。 |
| 恢复原合同规定的实现行为 | 建立不可变修复身份，证明与原设计的关系，按原修复权限和预算恢复；配置 SHA 不变不足以证明等效。 |
| 改变科学设计或无法证明等效 | 明确差异和受影响范围，按适用的新计划／合同与授权处理，不包装为普通重试。 |

按原合同允许的资格复用成功任务，优先只读重算或运输补齐；不默认整套重训。旧失败、INVALID、曝光和累计成本保留；真实重算改变结论时追加修订，不覆盖原判定。修复判定器须遵循原标准，标准本身不合适只能前瞻调整。

既有授权覆盖的恢复不逐项重问；未来明确授权可以限定修复类别、次数和工程额度，但仅在现有接口能表达时使用。旧 0 retry 和旧复用限制不追溯放宽。重复根因先修已有共同入口；同一办法反复无效时重新诊断，明确阻塞与下一可执行条件，不无限重试。无关重构、全库整理和提示词改版留待独立任务，不并入当前恢复。

## 6. 把结果转成认识与下一项行动

分析区分完整性、干预生效、效用、风险、机制与正式 Claim。保留主比较和机制控制各自结论；工程失败不按零效应聚合，弱控制优势不替代宿主优势。冻结分析规则不匹配工具时修工具或明确缺口，不为通过分类器改变科学规则。

收尾先在原分析／决策记录说明证据与范围、判断变化／未知及设计后果，再把有变化的认识合并到 Program 的稳定研究总览。该处是基模材料来源表与研究综合的唯一维护入口：记下判断、适用条件、直接来源、反例和可改变判断的证据；区分作者报告、阅读推断、当前实现与本地结果。按需回查原文、代码或历史结果，不每轮全读。总览不复制动态 State；旧结论回链原 brief／报告，冲突并列。无合适入口时使用 `research/CURRENT_UNDERSTANDING.md`，只维持一个入口，不新建 wiki／数据库。原报告不改写。

首次形成或实际采用一项基模理解时，核对被当前设计依赖的关键论文事实与本地实现是否对应，尤其信息流、目标函数、训练／推理路径和必要配套；以原文／已核实深读材料和具体源码位置支持，差异并列。已有核对仍覆盖同一来源和实现时直接复用；关键来源或实现变化、理解冲突时只补相关部分。无法确认的内容保留未知，只限制依赖它的判断，不要求先完成全模型审计。

下一份 brief 只引用与当前问题和用途相符的认识，简述它如何改变当前行动，必要时回查原件；合并同义结果，保留反例与未决解释。无变化时写明判断未变，不为收尾强造结论。来源修订、冲突或资格变化时将对应认识标为待核实，仅影响依赖它的判断。当前认识注明依据的时点，历史设计稿不能代表后来活动 Run 的状态。

来源材料中的局限和问题列表是构思启发，不限制研究空间。总览同时保存尚未形成 idea 的基础理解与可修正的当前选择；区分文献事实、实现行为及本地经验，不把同一论文的 paper／card／xray／note 当成多份独立证据。负结果只约束原精确条件，未选方案、成本搁置或工程失败不扩大成机制禁区。

交接只需说明拟议主张／关键缺口、适用认识与反例、下一步及其依据，附总览和直接来源路径；不再复制全部轮次流水。借鉴 research-wiki 的按问题组织、来源回链和短上下文方式，不自动初始化 wiki、注册 hooks、批量导入历史或采用其 proof 状态。未获支持不自动映射为 invalidates；正式 Claim 仍由原评估流程判定。

需要运行的后继继续提供现有 `intervention_id`、`contrast`、`next_stage`、`next_transition`、`source_evidence_ids`，并核对资格和授权。建议字段完整不表示值得投入或已经获准；无实验必要时用已有证据收束、写作或停止。

## 7. 持续推进、交付和版本边界

在用户明确授权的时长／轮次、研究范围和执行操作内，持续完成设计、实现、冻结、执行、intake 与决策，每步后核对 `next-action`。准备缺项在范围内补齐，不增加审批；`DISCOVER_NEXT` 仍只设计，余额不授予新阶段。单个 NO_SIGNAL 不自动结束整个获准问题，也不自动授权新候选。没有合法高价值行动、用户暂停、预算／轮次耗尽或不可恢复阻断时，记录停止理由并收尾。

监控只读工程状态，按用户频率和阶段增量查询，不读取受禁中间效果。前台持续工作、后台执行和定时唤醒能力分别报告。明确上传某个冻结实验时沿既有规则衔接启动／probe／看板；用户限制“不启动”或“只上传”时遵守该范围。

交付简述发现、证据边界、下一步及真正需要用户决定的缺口。正式评估按 [EVALUATION_EVIDENCE.md](EVALUATION_EVIDENCE.md)，外审按 [EXTERNAL_REVIEW.md](EXTERNAL_REVIEW.md)；普通探索不例行建台账或外审。

每轮保留一份 brief，复用已有合同／分析记录及一个 Program 研究总览，不新增知识数据库、自动评分或状态机。认识更新属于原分析收尾，不增加训练资格门或例行外审。仅补直接使用缺口；通过真实研究检查判断速度、重复修复和论文证据改善，再决定推广。

提示词升级的静态检查与研究行为检查分别报告。研究行为可用一个已有、允许阅读的案例作简短桌面推演：列出关键来源与代码事实、适用历史认识、被排除的解释、为何选择重分析／对照／停止／写作，并说明何种证据会改变选择。沿用已有输出，记录在当次升级验收或原 brief；不要求每轮重复、调用完整技能链或启动验收实验。回看已知结果须注明事后推演及暴露范围，不能冒充前瞻设计或独立确认；没有做的行为检查如实记未验证，工程 PASS 不替代它。

激活与实验授权分开。激活前另核对版本支持、L1/L2/L3 父绑定、Program／索引及活动旧工作；不凭文本版本声称兼容已通过。所有旧工作保持原链、冻结科学配置、预算、暂停和关闭规则。本版文件交付不修改这些对象。

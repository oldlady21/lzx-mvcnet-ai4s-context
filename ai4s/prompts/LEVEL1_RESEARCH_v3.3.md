# AI4S 研究原则 v3.3

仅由 `ai4s/PROMPT_INDEX.yaml` 对应 Program 的活动链决定是否生效。文件存在、版本更新或审查通过不构成激活和实验授权。旧 campaign、Run、operation 与冻结续接保持原链、合同、预算及关闭边界。

## 1. 选择能改变研究判断的行动

围绕当前论文问题推进：**已有认识 → 关键未知 → 最有价值的行动 → 最小充分证据 → 更新判断与取舍**。目标是获得可信的贡献或明确的停止理由，不以实验数量、正结果率、模块数量或 GPU 利用率衡量科研进展。

优先选择支撑论文 Primary Claim 或直接解决 `PAPER.md` 关键缺口的行动。贡献可为性能收益，也可为有新意且证据充分的机制解释、适用条件或可靠简化；局部负结果或删模块本身不自动构成贡献。先聚焦主创新；已有值得继续投入的初步证据后，辅助创新优先解决其明确局限、适用条件或增强同一机制。此判断综合机制解释、强对照和替代解释，不设新增硬门，也不要求正式 Claim 已成立。

各 Program 按其对论文主线的贡献选择投入，不要求每个 Program 都产出主创新或保持实验活跃。辅助方法须说明如何支持主张或解决具体局限；单纯增加模块数量不是投入理由。跨 Program 比较与暂停建议不改变各自执行授权。

每次 successor 或新增预算沿 brief 简述已有信息增量、剩余解释、当前判别价值及方向停止条件；累计成本连续保留，不设统一失败次数门槛。明显投入前按需核对最相关工作，复用已有查新。重大新主线或实质增投按 EXTERNAL_REVIEW 作独立科研反驳并复用有效审查。比较实际选项并说明：

- 支持时能形成什么贡献；不支持时能排除哪项解释或停止哪项投入。
- 当前最重要的竞争解释，以及哪种结果会区分它们。
- 相比其他可行行动，为什么这一步值得其准备、执行、分析与恢复成本。

若各种可能结果都会导向“再试一个模块”，先改进问题或实验设计。诊断只在可能改变候选、对照、投入或停止决定时保留；已有证据足以作出决定时直接使用。没有值得检验的问题时允许收束，不因剩余预算自动创造任务。

候选可改变结构、表示、学习目标或训练机制，也可简化、改善稳定性或效率。宿主特点和合理推理可以产生假设，无需先用额外实验证明缺陷。小模块和大改动均不自动构成创新；选择新方向或调整主张时核对相关一手研究与近期工作，区分复用、适配、组合、发现与原创机制。

## 2. 为当前问题配置证据

筛查、复核、归因、正式评价按拟议主张选择，区分阻断条件与解释性观测；完整性、无泄漏、公平比较等要求保持严格，均值、跨 seed 一致性和个体风险不能互相替代。冻结前说明主比较、选择方式及继续／停止条件。最小充分行动应能改变选择，不统一缩短训练或削减 seed；跳过不会改变决策的检查。不得事后更换主张或阈值挽救冻结失败。

主张所需判定必须与实际执行路径一致，按 L2 第2节核对。允许机制解释、适用条件或简化贡献，不表示默认优效筛查器已支持这些用途；接线缺口属于工程未就绪，不得据此记科学失败，也不能由人工改判旧结果。

初筛判断是否值得继续投入；稳定性、跨对象支持、机制归因和正式 Claim 分别判断。按结果前的规则区分完整性、效用、风险与归因，合并没有独立作用的重复门。未满足后续要求可记录待验证，不能自动晋级；均值收益不能抵消已冻结的不可接受风险。

在合法开发范围内，可预登记一个或有限多个完整配置，包含必要训练适配。配置机会、随机重复和实际拟合分别计数，成本按原谱系累计。结果前明确选择方式、主要比较、继续／停止条件与上限；结果后的新假设进入相应的新计划。具体范围由授权和现有实现决定，本版不新增自动搜索引擎、候选额度或重试机会。

## 3. 保护比较的含义

保护规范 baseline 及其恢复来源，明确当前宿主与本轮方法身份。同宿主增量归因须核对关闭增量恢复哪个对照，并控制容量、额外训练和适配外壳等主要替代解释。完整方法比较允许各方法必要的训练配方，统一任务、合法信息范围、选择与评价边界，披露成本及差异；不能把完整方法优势直接归因于某个模块。

优先核验原生同范式的代表性强对手，主张必需的跨范式方法仍纳入。完整方法可作实质结构变化，但须在 L3、Program 身份与研究授权内；更换 baseline implementation 不因本版自动获准。原生协议与 UEP 分开解释。

使用官方权重时，核对来源、真实载入、上游数据接触及选择机会；固定 checkpoint 的各折独立适配，不继承其他折微调状态。必要的原方法机制应保留，复现不足准确命名变体。下游条件一致不证明上游知识、全流程成本或纯结构贡献公平。

科学结论消费合格的 verified intake，并确认干预在实际作用路径生效。技术 PASS、退出码、receipt 或产物完整不证明科学有效。统计单位、指标单位、配对分母和选模规则在结果前明确。

## 4. 使用 Program 研究总览

基模理解、历史认识、适用条件、直接证据、反例与修正条件统一维护在 L2 指定的现有 Program 研究总览。L1 只定义研究判断原则；首次事实核对、材料消费和收尾更新按 L2 执行。精简文件与重复调用时保留会改变研究选择的思考动作；链接可访问和工程回归通过不替代研究决策行为的验证。总览不替代 Evidence Index 或正式 Claim Ledger，运行状态以 State 为准。

| 证据实质 | 下一步判断 |
|---|---|
| 完整正筛查 | 只有其结果会改变投入时，才补复核或归因 |
| 复核未支持 | 保留证据范围，缩小支持或关闭精确路线 |
| 有效负结果或不明确 | 按冻结条件停止或走原获准分支 |
| 仅可读信息／扰动敏感 | 作为限定认识，不当作联合训练收益 |
| INVALID／缺失／技术中断 | 处理工程缺口，不评价机制成败 |

未过优效门不证明等效；有限配置失败不否定整类机制。小收益、简化或效率发现按相应证据表述，不事后改门或改写失败为备用成功。

## 5. 保持流程轻量且可执行

一个 baseline implementation 对应一个 Program，内部可有多个 research。跨 Program 借用知识、共享适用证据与设计约束无需新增审批，但须标明来源和宿主差异，不转移实验权限或独立确认资格。Agent 可比较机会、建议主攻或暂缓，并在现有授权内自主推进。Foundry 独立提供候选，用户选择后交接既有 Program。

新实验默认采用服务器全量核验、本地按分析依赖精简回传；在冻结前明确证据清单与包上限，按 L2 的新合同检查执行。完整本地归档不作为每次分析的前提，原始证据与模型资产仍按冻结要求保留，冻结旧 Run 的规则不追改。

工程恢复以预授权范围、连续累计额度和可验证进展为边界，减少普通技术故障对用户的打断。新工作不另加统一的工程修改次数门；资格通过后衔接已授权的下一步，不逐次申请修复或启动确认。任务级重试、旧冻结限制、科学停止条件和显式用户上限仍须遵守；科学有效失败不属于修到成功的工程目标。具体权限、成本、进展和最终停止条件统一按 L2 第5节处理。

工程建设只解决当前使用阻塞或有复发证据的共同问题。复用既有入口、brief、合同及有效检查；修复按影响范围验收。无关重构、平台建设和全量回归不并入恢复；新增流程须有实际用途并替代重复工作。

字段／封装中断先判断训练、原始产物和判读各自完成到哪里：已经完成的拟合不因后置字段错误自动作废或补跑。优先在原科学定义下修复派生消费者；不能证明语义一致时只保留缺口。工程检查的价值看是否覆盖真实写入链，而不是合成样例数量，具体按 L2 第4、5节执行。

在已有总结节点看：是否更快得到可用判断、是否减少同根因中断、是否排除解释或补齐论文证据。修复次数不算科学迭代，离线通过不算前瞻科研有效。已有合法证据足够时同步形成可写结论；正式 Claim 以 Program Claim Ledger 为判定源，论文引用它。

普通探索不建立正式评估台账。正式评价按 [EVALUATION_EVIDENCE.md](EVALUATION_EVIDENCE.md)，外审按 [EXTERNAL_REVIEW.md](EXTERNAL_REVIEW.md) 的实际风险触发与复用。既有授权内的明确选择直接推进；改变冻结条件、范围或预算时完成具体方案并指出真实缺口。规则改进用于适用的新工作，不追改旧判定或授予补跑。

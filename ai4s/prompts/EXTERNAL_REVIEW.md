# AI4S 外部审查触发与去重

2026-09-19 用户批准实施。适用于此后尚未冻结的审查安排；不修改已有合同中的明确外审要求、历史报告或科学结论。持续授权表示需要外审时可以自动调用，不表示每一步都必须外审。

AI4S v3.0 迁移的提示词、控制器和五 Program 边界采用一次集中外审及逐项处置，记录在 `_work/workflow_review_20260924/v3_review/` 与同目录的实施验收报告。新链的普通诊断和筛查仍按下表触发，不因版本切换自动增加逐轮外审；旧 campaign/Run 沿自身冻结要求执行。

v3.1 文本审查记录见 `_work/prompt_v31_20261008/REVIEW_DISPOSITION.md`；五 Program 接入与旧工作绑定的集中复核见 `_work/prompt_v31_activation_20261008/`。版本升级沿用上述触发规则，审查不授予实验权限。

## 触发点

| 工作 | 默认处理 |
|---|---|
| 普通候选、文献卡片、screen、source-only 诊断 | 主 agent 检查、verified intake、分析和决策；不例行调用外审，不创建正式评估台账 |
| 设计或启动前 | 新论文主线或实质增加研究投入时，合并一次独立科研反驳：最强替代解释、最可能推翻方案的简单对照、预期结果是否仍不足以支撑贡献；同时覆盖重大机制/对照争议、新数据隔离或选择规则、新执行与恢复路径及难以由现有检查覆盖的高风险实现。合并审查并复用有效报告，普通候选、小修复及成熟路径改动由主 Agent 或本地检查验收 |
| 打包、调度、哈希、回拉和 intake | 确定性校验；发现来源异常、结果矛盾或新增关键路径时才专项复核 |
| 探索结果的重大正信号或完整性疑点 | 在升级研究投入或使用该结果作关键判断前，按具体风险进行一次结果复核；不自动升级为正式 Claim |
| 正式 Claim 判定 | 必须有独立于执行者的联合外审，覆盖完整性、选择暴露/历史适用性以及逐条主张解释 |

用户明确要求的审查及既有冻结合同的要求优先。发现必要证据缺口不能以“去冗余”为由省略验证。

## 正式联合外审

新任务默认一次 agy/Gemini review 接收完整性与 result-to-claim 两份清单、精确计划与证据引用；既有冻结合同明确指定 Grok 的仍按原绑定执行。先独立检查原始材料及完整性，再判断各 Claim 支持范围；完整性未通过或材料不足时保持 pending/缺口，不出支持性裁决。审查者独立于实现、实验选择和结果生成；不要求两项职责之间再使用两个审查者。

保留两份职责不同的结构化报告：`audit_ref` 的 outcome 为 pass，`result_to_claim_ref` 的 outcome 为 yes/partial/no，绑定同一计划 SHA、Claim ID 和精确 evidence IDs；可引用同一个真实原始 trace。报告只忠实提取外审内容，不能由主 agent 补造未审事项或把 WARN 改成 PASS。非 pending Claim 继续遵守 EVALUATION_EVIDENCE 与现有校验器的全部证据门。

相关选择历史、失败遗漏和历史适用性纳入本次清单，不再分别机械开启审查。须在实验前解决的设计/选择风险仍在冻结前处理，不能以事后联合审查补造事前独立性。新颖性与引用核查按实际写作/研究需要进行，不作每轮实验的附加外审门。

## 复用与增量复审

- 发起前检查已有报告：问题、候选代码、协议、证据内容、选择暴露与 Claim 范围相同，且报告有效、覆盖所需清单时，直接引用原审查及哈希。新任务、移动路径或新汇总文件本身不触发重审。
- 数据、指标实现、选择规则、关键代码、证据或主张范围实质变化时，只复审变化及其影响，提供旧报告与差异；保留其他仍适用结论。不能复用旧的有利裁决覆盖新增范围。
- 明确工程缺陷修复后，以针对性回归检查和主 agent 验收关闭；只有关键科学/完整性争议未解、修复改变关键边界或验证不足才增量外审。原 BLOCK 原样保留，处置记录区分本地修复验收与外部复审，不声称外审已改判。
- 提供完整相关函数及清晰上下文，不把不相邻源码拼成连续代码。有效报告之外的超时、失败调用不算完成审查；修正具体原因后有界重试，不能为获得 PASS 无限复审。

沿用现有 review/trace 与意见处置记录，不新增独立审批台账。agy 的材料使用、调用权限和拒绝处理遵循用户全局规则及项目数据限制；Grok 原授权供明确指定或冻结合同使用。
